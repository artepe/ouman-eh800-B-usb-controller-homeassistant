# Danfoss MCX and DEVIreg 330 – tentative Open HVAC support

**Validation: experimental; no hardware tested.** A photo of a panel
display is insufficient to identify the controller PCB, installed application,
available communication daughterboards or exact external wiring. These are
**two different kinds of equipment**, not one shared bus.

## 1. Danfoss MCX – site-programmed Modbus monitoring

Danfoss MCX is a programmable controller family. Some variants support RS485
**Modbus RTU slave** and also carry CANbus. **CANbus is not Modbus**.
The Modbus register/coil export is generated by the particular application
using MCXShape, so there is **no universal MCX zone register map**.

Official product family overview:
https://www.danfoss.com/en/products/dcs/electronic-controls/products/programmable-controllers/programmable-controllers-mcx/

One Danfoss *air-handling application* manual (not a map for this customer's
panel), section 16, documents serial address, baud (often 19200 baud),
8N1/8E1/8N2, and application-exported Holding Registers / Coils:
https://www.danfosscenter.ir/wp-content/uploads/2025/06/AHU_DKRCC.PS.RI0.H2.02__520H7502_AZ.pdf

### Commissioning in OpenLVI

1. Read the exact **MCX PCB model and application/version** from the
   nameplate and project documents. Verify an **RS485 Modbus** port and its
   wiring; do not connect an RS485 adapter to a CANbus connector.
2. Obtain the installed program's actual **MCXShape exported variables**
   table or a verified integrator-supplied Modbus list. Document unit address,
   baud, parity, function code, word ordering, scales, and zone names.
3. In OpenLVI: **Danfoss → MCX (site-programmed) → Modbus RTU**, or choose
   Modbus TCP *only if the installed RS485 gateway correctly bridges RTU*.
4. Supply a site-specific **read-only JSON profile** in the existing field;
   it must use real, documented addresses. The following is a JSON **format
   illustration, not a real MCX address**:

   ```json
   {
     "registers": [
       {"key": "zone_1_temp", "name": "Zone 1 measured temperature",
        "address": 123, "area": "holding", "kind": "s16",
        "decimals": 1, "unit": "°C"}
     ]
   }
   ```

5. Compare every readout with the physical controller. A discovered bus
   does not imply individually controllable outputs. MCX Coil exports
   are **not** supported by the generic register JSON parser.

**Current Open HVAC behavior:** model selection and read-only Modbus
**holding/input register monitoring**, requiring a supplied exact map.
No default addresses, no auto scan, no coils and **no Modbus writes**.
To add price-driven zone setpoint control, first obtain the exported
writeable variable map, source program and manufacturer-confirmed safety
limits. A separate reviewed implementation and physical bench test will
be necessary.

## 2. DEVIreg 330 – 5°C economy setback, not Modbus

The **DEVIreg 330 (+5 to +45°C)** model supports a fixed **5°C reduction**
through an external timer input. It **does not** have Modbus or a digital
per-zone temperature API.

Danfoss documentation (item 140F1072):
https://devi.com/en/products/thermostats/outdoor-applications/devireg-330

Official installation/wiring guide (see pp. 6–7):
https://assets.danfoss.com/documents/latest/370401/AQ087986471595en-020207.pdf

**Important:** the guide's economy/timer terminals must be treated as
**mains-referenced**, not assumed to be a 3.3 V, 5 V or voltage-free input.
The thermostat itself must have continuous power. A qualified electrician
must establish the correct phase/neutral, terminal numbers, contact ratings,
protective separation and routing from the exact installation diagram.
Do not wire a microcontroller pin or low-voltage relay-board signal
directly to those terminals. Do not switch off supply power to
perform price scheduling, and never bypass thermostat/safety protection.
Other DEVIreg 330 ranges do not have the same setback function.

### Per-circuit spot-price control in Home Assistant

Install a correctly rated relay/contact interface per circuit, with its
existing 5°C setback input **professionally commissioned** and exposed
as a Home Assistant `switch.*` entity: **ON = economy setback**;
**OFF = ordinary thermostat setting**. Ensure the installed relay
**defaults to the normal/no-setback state if power, network or automation
fails** (verified in hardware, not just assumed from software).

Import
[`blueprints/automation/openlvi/devireg330_price_setback.yaml`](../blueprints/automation/openlvi/devireg330_price_setback.yaml)
via Home Assistant's blueprint import or copy it under
`/config/blueprints/automation/openlvi/`. Create **one automation per
individually controlled circuit**. Each automation selects:

- Price sensor producing a numeric **cents/kWh** value;
- Commissioned setback request switch for that circuit;
- Enter-setback price threshold and a **lower** exit threshold (hysteresis);
- Price data maximum age (default 90 minutes).

Behavior: at expensive prices the blueprint requests setback. At cheap
prices it releases setback; between thresholds it keeps the last request.
Missing, nonnumeric or stale price returns to the **normal thermostat
setting**. Restarts are handled by a Home Assistant start trigger, but
software cannot guarantee normal state during an HA outage. Verify hardware
fail-safe behavior. Confirm that your price sensor's units really are
**c/kWh**, not **EUR/kWh**, and decide which transfer fees/taxes to include.

No direct DEVIreg status feedback is available by this method.
Separate metering and temperature sensors are needed for feedback, and
local thermostat temperature limits remain authoritative.

## Information required to progress beyond experimental

- Both MCX PCB type labels, project-specific application/firmware version,
  and an MCXShape export/register list (redact secrets).
- Confirmation of which displayed channels drive which contactors/outputs.
- DEVIreg 330 item codes (not just appearance), exact circuit list and
  wiring drawing showing the terminal/timer input.
- One supervised read-only RS485 capture (unit address, baud, parity) and
  physical display readings for cross-checking.

**Do not assume:** a panel label = Modbus register, a displayed zone = an
independently written coil, or that the DEVIreg timer terminals are SELV.
