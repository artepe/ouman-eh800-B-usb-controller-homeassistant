# Danfoss MCX – tentative Open HVAC support

**Validation: experimental; no hardware tested.** A photo of a panel
display is insufficient to identify the controller PCB, installed application,
available communication daughterboards or exact external wiring.

## Site-programmed Modbus monitoring

Danfoss MCX is a programmable controller family. Some variants support RS485
**Modbus RTU slave** and also carry CANbus. **CANbus is not Modbus**.
The Modbus register/coil export is generated by the particular application
using MCXShape, so there is **no universal MCX zone register map**.

Official product family overview:
https://www.danfoss.com/en/products/dcs/electronic-controls/products/programmable-controllers/programmable-controllers-mcx/

One Danfoss *air-handling application* manual (not a map for this customer's
panel), section 16, documents serial address, baud (often 19200 baud),
8N1/8E1/8N2, and application-exported Holding Registers / Coils:
https://www.danfosscenter.ir/wp-content/uploads/2025/06/AHU_DKRCC.PS.RI0.H2.02__520H7502_AZ.pdf

### Commissioning in OpenLVI

1. Read the exact **MCX PCB model and application/version** from the
   nameplate and project documents. Verify an **RS485 Modbus** port and its
   wiring; do not connect an RS485 adapter to a CANbus connector.
2. Obtain the installed program's actual **MCXShape exported variables**
   table or a verified integrator-supplied Modbus list. Document unit address,
   baud, parity, function code, word ordering, scales, and zone names.
3. In OpenLVI: **Danfoss → MCX (site-programmed) → Modbus RTU**, or choose
   Modbus TCP *only if the installed RS485 gateway correctly bridges RTU*.
4. Supply a site-specific **read-only JSON profile** in the existing field;
   it must use real, documented addresses. The following is a JSON **format
   illustration, not a real MCX address**:

   ```json
   {
     "registers": [
       {"key": "zone_1_temp", "name": "Zone 1 measured temperature",
        "address": 123, "area": "holding", "kind": "s16",
        "decimals": 1, "unit": "°C"}
     ]
   }
   ```

5. Compare every readout with the physical controller. A discovered bus
   does not imply individually controllable outputs. MCX Coil exports
   are **not** supported by the generic register JSON parser.

**Current Open HVAC behavior:** model selection and read-only Modbus
**holding/input register monitoring**, requiring a supplied exact map.
No default addresses, no auto scan, no coils and **no Modbus writes**.
To add price-driven zone setpoint control, first obtain the exported
writeable variable map, source program and manufacturer-confirmed safety
limits. A separate reviewed implementation and physical bench test will
be necessary.

## Information required to progress beyond experimental

- Both MCX PCB type labels, project-specific application/firmware version,
  and an MCXShape export/register list (redact secrets).
- Confirmation of which displayed channels drive which contactors/outputs.
- One supervised read-only RS485 capture (unit address, baud, parity) and
  physical display readings for cross-checking.

**Do not assume:** a panel label = Modbus register, or a displayed zone = an
independently written coil.
